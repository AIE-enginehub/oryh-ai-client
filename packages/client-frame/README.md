# ORYH Client frame

This directory publishes `@oryh/dsh-client-frame`, with a Host loader entry, browser `./client` module and `dsh.client` dependency manifest. There is no standalone page or HTTP server. The business pages are separate page plugins (`packages/client-*`): each mounts its own Remote namespace, registers its menu entry through `ctx.oryhClientPages`, and injects its page into the `oryh.page` keyed slot this frame declares (and, when it handles the agent's commands for its pages, a component into the `oryh.bridge` list slot). A page plugin takes nothing from this package but its types. What it needs of the frame reaches it through those two slots: owner props for what the workbench knows as it draws the page (the bound session, navigation, Chat's actions and activity, the menu, the words), and the slots' own inject for what this plugin's services hold (its Remote, and the pane's two sources, which the renderer turns into `usePane` and `usePaneLocal`). The hooks and shared page pieces a page draws with are in the static library `@oryh/ai-client-kit`, bundled into each plugin. No component here or in a page reads a React context: an entry's props are its `face`, passed down as a prop, and the kit's hooks take it as their first argument. Nothing is a module-level store either — the menu mirror, the kept preferences and the pane are instances this plugin makes when it starts, read through hooks the renderer makes over them. Every sentence is in a word list (`@oryh/ai-client-kit/dictionary` for this plugin and the kit, `words.ts` in each page plugin), registered with Harness's locale service.

The ORYH Bundle disables the default layout. This plugin provides the sole `root` and public `ctx.layout` service: business navigation and the native sidebar on the left, root-scoped `oryh.business` in the center, and the native session-maybe `conversation` on the right. Native `rightbar` remains a session-scoped overlay; `shell.overlay` is retained. No private Harness source or conversation component is imported.

Root geometry uses a Harness `defineStore`. Business pages remain mounted across navigation and chat visibility changes, independently of Session selection. That is why the two page slots are root-scoped and not session-scoped: Harness mounts a session-scoped entry afresh when its session changes, and a page holds work that has to outlive a change of conversation. Narrow screens switch between business and chat. A refresh or unload clears unsaved edits.

Generated Remote descriptors mount through the public Gateway and wait for `remote.oryh`. Business components receive that transport; each page plugin mounts its own domain namespace beside it. Locale, theme, styles and slot registrations are lifecycle-owned. So is the pane's binding: a service created when the plugin starts (`pane-service.ts`) binds the session, follows the agent's commands and syncs what the pane shows; the workbench only tells it which connection, session and page are on screen.

The current upstream renderer has a root-gap error during development hot replacement. The Profile disables `client-hmr`; save drafts, stop the server, build and restart when upgrading. Normal plugin unload/re-register is covered by public SlotCore/Cordis lifecycle tests.

The native conversation is the only chat. Chat-driven navigation, list columns, inventory query fields and form filling are enabled: this package syncs the current page, its list or detail context and unsaved form fields to the Host through the generated Remote, and applies the commands the Host issues, acknowledging each with the command id so the waiting tool can confirm the page actually changed. The page plugins those abilities were written for — timesheets, expenses, projects — are no longer in the bundle; what remains in use is the to-do page, lists and custom pages. A write the agent makes is confirmed in the conversation, not in a page. The plugin migration history is kept in the private source repository (docs/14), which is not published here.
