# macOS 本地测试包

在 Apple Silicon Mac 上执行 `pnpm desktop:mac`。先按 `pnpm harness:setup` 准备锁定的上游，再安装本仓库依赖。脚本使用 Harness 官方 unsigned Desktop 构建入口，构建 ORYH 插件，组装 `.app` 和 `.dmg`，输出到 `dist/mac-arm64/`。没有开发者证书或 Apple 公证；仅适用于本地测试。

应用继续使用官方 Electron 壳、Host、Session、模型设置、Gateway 和 Profile 生命周期。ORYH 启动文件只设置产品身份、独立的数据目录，并将外部 `@oryh/dsh-bundle` 加入官方 `desktop` Profile。产品插件随安装包携带，无需本机 Node、pnpm 或源码目录；应用名称和图标在分发产物中替换，不改上游源码。第三方依赖的版本差异用独立依赖目录保留，不能覆盖 Harness 的单例包。

数据默认位于 `~/Library/Application Support/ORYH AI Client/`。`ORYH_DESKTOP_DATA_DIR` 可指定独立测试目录；应用不会导入现有 Harness 的凭据、会话或工作区。ORYH 服务器和模型由用户在应用内配置，安装包不携带任何凭据。

`build.json` 记录客户端提交、锁定的 Harness 提交、构建时间及 DMG SHA-256。`--reuse-shell` 和 `--reuse-client` 仅供同一工作区诊断重打包时使用；正常构建不要跳过编译。

验收至少包括：挂载 DMG 后复制并启动；使用独立目录冷启动；检查原生壳、Profile 与插件实际装载；连接 ORYH 测试环境；待办查询与 Chat 导航；表单预填且不写业务数据；重启恢复；核对签名和产物哈希。构建通过不代表业务端到端验收通过。

## 启动与模型配置

首次启动直接进入 ORYH 工作台的“连接企业”页面：选择 ORYH 服务器，在浏览器登录并授权。无需 DeepSeek 账号或模型密钥即可进入工作台和使用已授权的业务页面。模型独立在左下角“模型与设置 → Models”配置，保存后在聊天框选择模型；连接企业不会自动取得模型服务的访问权限。

当前锁定的官方 Electron 壳没有公开的产品启动引导开关。`shell-adapter.mjs` 只适配本仓库打包生成的 `lib/main.js`：关闭统一欢迎页判断；启动时只读取原生设置中的语言偏好，不再请求模型平台账号状态；停止订阅模型平台账号的登录与过期事件。否则在 Profile 停用账号控制器后，原生壳会因启动账号 RPC 失败而无法进入工作台。适配不修改上游检出、不伪造登录状态、不写占位密钥，也不移除 Host 的本地认证或 ORYH 的业务授权。适配匹配项任一缺失或重复立即终止打包，升级 Harness 时须复核。`node --test deploy/desktop/shell-adapter.test.mjs` 覆盖启动语言保留、账号 RPC/订阅不再调用及版本漂移的约束。

外部 Profile 停用 DeepSeek 账号 UI、账号控制器、账号服务和账号模型提供方。设置不再显示 Account 页、账号余额或 DeepSeek Account 模型行，保留 API 提供方的 Models 设置和模型选择器，并关闭自动官方账号引导。已有 API 配置、凭据与 ORYH 企业连接不变；不会删除用户磁盘上原有的模型平台凭据。聊天缺少密钥、密钥不被接受或模型不可用时，通过公开的 `conversation.chat.node` 插槽显示 ORYH 双语指引；其余错误保留官方渲染器。原始会话失败记录不被修改。

## 企业凭据与旧登录迁移

ORYH 企业登录使用官方 Harness 的 `credentials` 服务，以 `oryh-connection` 拥有的 grant records 保存到个人 Harness 目录的 `.credentials.yaml`。它与模型密钥、官方账号记录采用不同的记录空间；账号、租户、服务器绑定写入企业 grant，并由 ORYH 的 `/auth/me` 再次核验。记录键同时包含应用数据目录和连接的摘要，避免不同本地数据目录中相同连接编号互相覆盖。

这是官方提供的本地文件权限保护机制，并非系统钥匙串加密；同一操作系统用户下运行的工具可能读取该文件。使用官方的原子提交、文件锁、重载与 0600 权限，不另建一份密钥文件，不把凭据放到 Session、日志、浏览器或安装包中。服务器版仍使用服务器托管凭据，不装载桌面迁移适配器。

只有升级前已有的连接记录，且 Harness 尚无对应 grant 时，才会读取一次旧系统钥匙串。首次迁移可能需要用户在系统弹窗中授权；拒绝时不反复弹窗，不删除旧登录数据，也不阻止发起新的登录。迁移先成功提交到 Harness，再使用该记录；旧钥匙串条目暂时保留用于恢复，不自动删除。新登录、迁移后的读取和刷新均不访问钥匙串。

旧钥匙串的同步原生读取运行于独立的只读迁移子进程。等待系统授权时不阻塞 Harness Host 的事件循环，桌面壳仍可读取启动设置并打开工作台；企业连接核验可继续等待授权，不以延长启动网络超时替代修复。凭据只经父子进程 IPC 返回 Host，不进入命令行、环境变量、日志或浏览器。授权失败、子进程异常退出或返回无效数据均拒绝使用；Host 关闭时终止尚在等待的子进程。成功迁移后的保存、身份核验、拒绝锁存和注销规则保持不变。

启动时加载连接若遇到 Gateway 传输失败（包括授权等待超过单次请求期限），工作台会保留等待状态并自动重试这段只读加载；延迟依次为 2、4、8、16 秒，最多 30 秒。授权完成后通过原有身份核验恢复连接，不需要点击重试或重新登录。Host 明确返回的业务拒绝不进入此重试，拒绝钥匙串访问及身份不符仍显示原有错误。重试仅用于启动读取，不重放登录、提交、审批等写操作；页面卸载或发起新操作会取消后续重试。

重新登录同一服务器、账号和租户会更新原连接，保留连接编号和会话关联，也可修复此前拒绝迁移的登录。不同服务器、账号或租户使用独立连接。拒绝迁移后的失败仅在本次 Host 生命周期内锁存；若未重新登录，下次启动仍可重试迁移。

本地并行验证包曾使用 `oryh-connection/vault-<数据目录摘要>` 汇总记录。升级时先将其中的凭据转换为带身份绑定的每连接记录，不读取系统钥匙串，也不删除原汇总记录。每连接记录始终优先，包括其注销标记；汇总记录已初始化但缺少某个登录时，也不会回退到旧钥匙串恢复它。格式损坏时拒绝使用，不静默回退。迁移缓存只记录完成或失败状态，不缓存可继续返回的密钥；外部删除凭据记录后，当前 Host 不会返回迁移时的旧值。

更早版本若已保存同一身份的多条连接，重新登录会修复最新的一条，工作台冷启动也选择同一条。启动自动选择还要求服务器、租户、环境、用户和员工身份全部一致；不同主体仍需明确选择。

退出连接会清除 Harness 中的凭据并留下不含密钥的注销标记，防止旧钥匙串条目使账号自动复活。升级后仍须使用 ORYH 服务端权限判断账号及租户；出现身份不符即拒绝业务操作。

## 桌面账号 Profile 隔离

服务器、租户、环境、用户、员工共同决定账号目录（`accounts/<SHA-256>`）。每个账号独立使用官方 Harness 的 home、`desktop` Profile、Session 存储、工作区注册、agent 配置和 Electron 浏览器存储。账号重新授权换发 grant 不改变其目录。新账号创建自己的工作目录，切回后恢复原来的会话和工作区；不是仅切换业务页面连接。

首次迁移依据 `business/chat-bindings` 的持久绑定识别旧聊天的主人。仅当所有绑定唯一对应一个账号时，该账号继续使用原 Harness home；其他账号无法加载它。无绑定、多个主人或环境归属不明的旧历史原样保留在旧目录，不能猜测归给最近登录者。模型/插件 Profile 定义用于初始化新账号，不复制聊天、工作区注册或派生存储。机器上原有的模型 API 凭据和带身份绑定的企业 grant 继续通过官方 `credentials-local` 的配置路径访问；不读取系统钥匙串，不写入会话。模型设置此后分别保存在各账号 Profile。

切换先经 Host 核验目标身份，再通过权限为 0600 的私有 Unix socket 通知产品 bootstrap。原生壳适配只在生成的入口加入 Profile 切换事件，复用 Harness 的运行任务确认及正常 Host 关闭流程；取消时不提交选择，也不展示新账号的业务数据。批准后保存目标、完整关闭旧 Host 并重启到新 Profile，清除旧内存中的模型上下文和浏览器当前会话。`DSH_HOME`、`DSH_AGENTS_HOME` 使用公开环境入口；产品代码不导入上游私有模块。

`node --test deploy/desktop/*.test.mjs` 覆盖根目录隔离、A→B→A 历史保留、旧历史归属、取消切换、私有控制及壳生命周期。工作台测试还要求 Profile 未就绪时不发布新账号连接，启动优先恢复原生壳已选择的连接。

2026-10-25 在独立数据副本上完成原生 Mac 验收：A→B→A→B 每次由壳自动关闭旧 Host 并载入目标 Profile。B 首次没有 A 的 Default workspace、会话列表及旧聊天；B 发出无业务工具的模型验证消息并正常收到回复。切回 A 恢复原工作区和完整旧聊天，再回 B 恢复其新会话与回复，未交叉显示。过程中未观察到钥匙串授权弹窗。完整 verify 通过 804 项 Vitest 和 13 项原生辅助测试。此记录属于测试副本验收，不表示已发布或替换正式安装。
